Scry Source code

Reading machine-written proofs, and checking what they prove

Scry is an open-source workbench for two questions a compiling Lean proof leaves to a person: how does this proof work? and does its formal statement say what the paper claims?

The problem

AI systems now write mathematics, and Lean proofs of it, faster than people can read them. OpenAI's openai/math repository alone holds about 720 manuscripts and some 26 million lines of Lean.

When Lean accepts a proof, it settles the formal statement, and nothing more. The statement can still say less than the paper: an extra assumption, a relaxed bound, a normalization dropped inside a definition. And a machine-written proof that Lean accepts can still be very hard for a person to follow.

What Scry does

  • Outlines of whole results

    A result and every theorem and definition it rests on. The outline separates what the theorem claims (the definitions you must read to check it) from how its proof is built. It also lists every assumption a proof never uses. openai/math's Navier–Stokes velocity result rests on 1,948 declarations across 152 files. Its outline loads as about 70 KB.

  • Step-by-step maps

    A proof as steps joined by "uses a fact from" arrows, taken from Lean's own record of the finished proof. You can propose a shorter route to one fact. Lean checks the whole changed file before anything is written, and the original file is never touched.

  • Statement checks

    Lean's kernel tests whether a statement's assumptions contradict each other, and whether its conclusion holds without them. An AI model compares the paper with the formal statement item by item. It can ask Lean to check claims of its own, and it must cite numbered evidence for everything it says.

  • A measure of those checks

    Scry plants known differences into copies of real statements, then scores audits that don't know which copy they have. So far the test is small: six planted differences, three statements, one model, one try each. Every plant drew a row naming a difference at its lines, and none was passed as "matches". Three are scored "conflicting", because a "matches" row about another item covers the same line.

Who says what

Every claim Scry shows says who made it.

Lean-checked
Only a real Lean run, ending normally, with no errors, no sorry, and only the three standard axioms.
Wiring checked (not proven)
Scry followed which facts feed which steps. It did not read the math.
AI's reading
What a model concluded, with citations to the evidence it rests on: a Lean check, or a quoted passage of the paper.

Each Lean check records exactly which files it ran on, by SHA-256 fingerprint. A stored result is reused only while every one of those files is unchanged.

Where it stands

Scry has been built since October 17, 2026. Its tests are written so they can fail. A mutation check breaks the code in about a hundred known ways and confirms that the tests notice every one. The repository lists what isn't done yet:

  • Scry doesn't yet run openai/math's own comparator, which checks that a solution states exactly the challenge's theorem.
  • Nothing yet records a mathematician's judgement of each benchmark row.
  • An audit isn't told which of a paper's other results are stated in other challenges.

The benchmark is small, and its planted differences were written by the project itself. The next step is plants written and judged by mathematicians.

How it was built

Scry is the work of Levi Banks (Hekswerk), who set its questions, its architecture and its standards of evidence. Coding agents and chatbots did most of the writing: Claude Code (most of the code), Antigravity CLI, Gemini and ChatGPT, each also a source of second opinions. Outside reviews are kept in the repository, with the changes they led to.

It is shared now so that the people who would use it, mathematicians and anyone checking AI-written mathematics, can say what it gets wrong.
